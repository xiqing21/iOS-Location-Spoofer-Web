# iOS Location Spoofer 实测排障总结

> 环境：iPhone 17，iOS 26.6.1，Shadowrocket，自部署面板
> 日期：2026-10-31
> 结论先说：面板已锁定、Debug 日志已显示改写成功，但地图仍显示真实位置时，
> 最后生效的关键是在**配置模式下，把 gs-loc 的两条规则置顶并强制走代理**。

## 现象

- 面板已锁定目标点，底部显示“已锁定”。
- Shadowrocket Debug 日志里已出现类似记录：
  - `[Location Spoofer] Patched 114 Wi-Fi, 0 Cell. Format: synthetic`
  - `[Location Spoofer] Patched 0 Wi-Fi, 122 Cell. Format: synthetic`
- 但地图仍显示真实位置。
- 飞行模式、重启手机、开关定位服务、切换全局代理均未让它跳过去。
- 同一台手机换另一家系统级 VPN 劫持服务后立即生效，说明手机本身的
  MITM 通路并没有被系统封死。

## 已排除的项（不要再在这里绕圈）

- 证书未信任：证书信任设置里 Shadowrocket 证书已是开启状态，且日志里
  wloc 请求带有 MITM 标记。
- MITM 域名没加：`gs-loc.apple.com`、`gs-loc-cn.apple.com`、
  `gsp-ssl.ls.apple.com` 以及高德相关域名均已在解密/MITM 列表里，
  日志证明拦截已经发生。
- 模块没装/没启用/还是旧域名：模块文件已核对，新域名、脚本路径、
  MITM 列表均正确，脚本确实在跑（有 Patched 日志）。
- 面板没锁定：面板底部“已锁定”才是锁定成功的标志。
- iOS 27 的强 TLS pinning：本机是 iOS 26.6.1，在项目 README 的支持范围内，
  不适用 iOS 27 beta 6 及之后的那条限制。
- 浏览器定位权限：面板的“定位”按钮只是把地图居中到真实位置，
  拒绝它只影响这个按钮，不影响手动锁定，也不影响 Shadowrocket 改写。
- 出口节点：改写在手机本地完成，节点只决定出口，与改写本身无关。

## 几个容易误判的点

### 1. 切全局代理测 DIRECT，是无效测试

全局代理模式下，Shadowrocket 的本地重写/脚本规则本身就不生效。
切到全局代理后还是真实位置，只能说明脚本被关了，不能证明
DIRECT 规则无辜，也不能证明 DIRECT 就是元凶。

要测规则，必须留在**配置（Config）模式**里测。

### 2. 代理日志详情页没有响应头，不代表没改写

单个 wloc 请求的详情页不显示响应头，所以看不到
`X-Location-Spoofer` 并不证明脚本没跑。
脚本是否跑过，要看 Debug 日志里的 Patched 记录。

但也要注意：Patched 只证明 Wi-Fi/基站子消息被改写并重新发出，
不等于系统最终采纳了改写后的位置。

### 3. 面板“已定位到当前真实位置”不是锁定

点面板的定位按钮，只会把地图居中到真实位置，底部仍会提示
“位置已移动，点锁定生效”。必须点“锁定”，底部变成“已锁定”才算数。

### 4. “User denied Geolocation”不是故障

那只是面板定位按钮被浏览器拒绝了地理位置权限，
不影响手动选点锁定，也不影响 Shadowrocket 的改写。

## 最终生效的做法

在配置模式下，在规则列表**最顶部**加两条规则：

```
DOMAIN,gs-loc.apple.com,PROXY
DOMAIN,gs-loc-cn.apple.com,PROXY
```

要点：

1. 全局路由必须是**配置**，不是直连，也不是全局代理。
2. 这两条必须在最顶部，放在原来“苹果服务”那条 DIRECT 规则之上。
   规则是从上往下先匹配先生效的，放下面会被先匹配的 DIRECT 抢走。
3. 策略选代理组（PROXY），不要选 DIRECT，也不要选 REJECT。
   如果策略列表里没有 PROXY 这个字，就选平时用的那个代理组。
4. 保存后 VPN 关掉再打开，目标 App 从后台彻底杀掉，
   定位服务关 10 秒再开，进地图点当前位置。
5. 复核：代理日志里 wloc 的规则应变为 PROXY，且 Debug 里仍有 Patched，
   地图应跳到锁定点。

实测结果：按上面置顶后立即生效。此前在 DIRECT 规则下，
脚本日志已有 Patched，但地图就是不跳。

## 完整自查顺序

1. 证书已安装且已信任。
2. HTTPS 解密已开，MITM 列表里有上面五个域名。
3. 模块已装、开关已开，且是新域名版本。
4. 面板已锁定，底部显示“已锁定”。
5. 全局路由是配置模式。
6. gs-loc 两条规则在规则列表最顶部，策略为 PROXY。
7. VPN 重连，目标 App 杀后台，定位服务开关刷新一次。
8. 看 Debug 日志：有 Patched，且 wloc 规则为 PROXY。

## 注意事项

- 模块链接里含有 token 参数，面板地址和模块链接不要公开，
  发截图前先打码。
- 不要把面板口令、地图 Key、证书、私有配置写进公开文档或截图。
- 订阅配置更新后，本地加的规则可能被覆盖，更新后要重新检查
  这两条是否还在最顶部。
- iOS 只允许一个 VPN 同时生效，测 Shadowrocket 时另一家 VPN 要关掉，
  反之亦然。
- iOS 27 beta 6 及之后因系统强 TLS pinning，MITM 类方案受限，
  本总结不覆盖那个版本。
